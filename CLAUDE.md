# Заметки по проекту RaiThai Spa

## Открытые вопросы (вернуться в следующей части)

Отложено сознательно — не начинать без отдельного подтверждения владельца.

### 1. Новые поля БД — согласовать список

База: **Supabase**, одна таблица `public.certificates` (12 полей), RLS включён без
политик, доступ только по `SUPABASE_SERVICE_ROLE_KEY` с сервера.

Аудит показал, что ТЗ требует полей, которых в таблице нет. Предложенный список
на добавление (существующие поля не трогать, только дополнять):

- `order_number` — человекочитаемый номер заказа (сейчас есть только техн. `id` uuid)
- `certificate_type` — на сумму / на программу
- `service_id` + `service_name` — какая именно программа куплена (сейчас не сохраняется вообще)
- `buyer_phone`, `buyer_email` — отдельными полями (сейчас склеены в `buyer_contact` через «·»)
- `sender_name` — «от кого» (форма собирает, в БД не уходит)
- `wish` — пожелание (форма собирает, в БД не уходит)
- `status` — active / used / cancelled (сейчас только boolean `is_redeemed`, «Отменён» выразить нечем)
- `redeemed_at` — дата использования
- `promo_code`
- `utm_source`, `utm_medium`, `utm_campaign`
- `sale_source` — источник продажи

Отдельно: `recipient_contact` после переделки формы всегда `null` — колонка осталась
от старого сценария, предложено оставить как есть, чтобы ничего не ломать.

### 2. `payment_status` всегда `paid`

`src/routes/api/certificates/create.ts` вставляет запись сразу со статусом «оплачено»,
без подтверждения от платёжного шлюза. Любой, кто дошёл до кнопки, получает
«оплаченный» сертификат. **Обязательно исправить до реального запуска** — статус
должен ставиться только из доверенного источника (вебхук или проверка статуса
Kaspi Pay / Freedom Pay).

### 3. Успешная запись в Supabase ни разу не подтверждена

Наблюдали только ответ `400 invalid_payload`, а он срабатывает **до** обращения к
Supabase. То есть связка «прод → база» на практике не проверена ни разу.

Дополнительно: локально в `spa-gift-zen` нет `.env`, ключи только в Vercel. В соседнем
клоне (`thai massage/.env.local`) ключ есть, но Supabase отвечает на него `401` —
похоже, ротирован или от другого проекта. Нужно проверить рабочие ключи и
провести один сквозной тест записи.

### 4. Почта администратора и почтовый сервис

Для уведомлений (письмо покупателю с сертификатом + письмо администратору о новом
заказе) нужно:

- адрес администратора — в задании остался незаполненный placeholder;
- выбрать сервис отправки: Resend / SendGrid / SMTP.

## Что нельзя ломать

Уже согласовано и переделке не подлежит без отдельной просьбы: бренд (логотип,
палитра брендбука, шрифты), первый экран и его тексты, форма оформления заказа,
карусель категорий, состав и цены услуг, два филиала (Петропавловск, Кокшетау).
