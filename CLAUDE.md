# Заметки по проекту RaiThai Spa

## Постоянные правила работы (добавлено 2026-09-18)

- **Репозиторий**: `alishkakarina-cloud/spa-gift-zen`, ветка `main` — единственный
  рабочий репозиторий этого проекта. Не путать с чужими форками/копиями.
- **Доступы уже настроены и авторизованы**: GitHub (push работает), Vercel
  (автодеплой из `main` через GitHub-интеграцию — стандартная работа с этим
  проектом не требует логина в Vercel CLI), Supabase (через `SUPABASE_URL` /
  `SUPABASE_SERVICE_ROLE_KEY` в `.env.local`, не в git). Не переспрашивать про
  доступ/авторизацию/логины на каждой задаче — просто использовать
  существующее подключение.
- **Стандартный рабочий процесс по умолчанию** для каждой завершённой и
  проверенной задачи: внести изменения → `bun run build` → закоммитить с
  понятным описанием → запушить в `main` (автоматически задеплоится на
  Vercel). Не спрашивать отдельного разрешения на коммит/пуш/деплой — это
  часть обычного завершения задачи, если явно не сказано иное.
- **Перед тем как сказать «готово»** — лично проверять результат (визуально
  и/или логически то, что менялось), не полагаться только на то, что сборка
  прошла без ошибок. У проекта была история циклов «исправил → сломал
  другое → откат → новая поломка».
- **Баг vs бизнес-логика**: явный технический баг/ошибка — чинить сразу, не
  спрашивая подтверждения на каждый шаг. Изменение бизнес-логики (не просто
  фикс, а решение, влияющее на то, как работает продукт) — сначала спросить
  подтверждение у владельца.
- **После каждого деплоя** — всегда присылать владельцу ссылку на прод
  (`https://raithaispa-certificate.kz`, либо актуальный на тот момент домен
  из Vercel) в финальном сообщении, не полагаясь на то, что он её помнит.

## Обновление 2026-09-14 — Supabase починен, ключ рабочий

Старый ключ в `.env.local` давал `401` не потому что был ротирован — PowerShell
слал User-Agent, похожий на браузер (`Mozilla/5.0 ...`), и новый механизм
Supabase «secret key» блокирует такие запросы как потенциальную утечку ключа в
браузер (`Forbidden use of secret API key in browser`). С явным
`-UserAgent "curl/..."` тот же ключ отработал нормально.

`SUPABASE_URL=https://potxhqqfuddnqsncbkxc.supabase.co`, ключ — `secret key`
(новый формат `sb_secret_...`, аналог `service_role`) из Dashboard → Settings →
API → Secret keys. Записаны в `thai massage/.env.local`.

**Сквозной тест пройден**: вставка тестовой строки в `public.certificates` и
последующее удаление через REST (`/rest/v1/certificates`) с этим ключом —
успешно. Значит связка сервер → Supabase рабочая, при условии что и в Vercel
